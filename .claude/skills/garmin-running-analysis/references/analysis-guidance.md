# Analysis Guidance

Use Garmin values as observations, not diagnoses. Make conclusions proportional to the available history and data quality.

## Recommended order

1. State the session type and outcome from distance, duration, pace, and training effect/load.
2. Add intensity context from average/maximum heart rate and the personal max-HR setting when available.
3. Inspect split progression for pacing stability, fade, negative split, or terrain-correlated changes.
4. Add cadence, power, or running dynamics only when recorded and relevant.
5. Add sleep, HRV, resting heart rate, and recovery context while noting that a short window cannot establish a long-term trend.
6. End with one or two specific, conservative takeaways tied to observed data.

## Comparison rules

- Compare like with like: similar distance, terrain, workout type, and environmental context when known.
- Prefer multiple sessions for trends. Describe a single run as a snapshot.
- Use absolute values and direction of change; avoid false precision from small differences.
- Do not infer causality between sleep/recovery metrics and performance from coincidence alone.
- Do not infer heart-rate zones when personal zone boundaries are absent. If useful, describe intensity relative to a known personal max HR and label it approximate.
- Distinguish elapsed time, timer duration, and moving duration.
- Flag partial final kilometer splits before comparing them with full kilometers.

## Recovery and health boundaries

- Frame HRV, resting heart rate, sleep, and recovery time as training-context signals.
- Do not diagnose illness, injury, overtraining, arrhythmia, or other medical conditions.
- If the user reports concerning symptoms, recommend stopping exercise and seeking qualified medical care rather than using Garmin data as reassurance.

## Suggested response shape

Lead with the direct answer in one or two sentences. Follow with:

- Key evidence: 3–6 metrics that support the answer.
- Pattern: pacing, intensity, efficiency, or recovery observation.
- Caveats: missing data, short history, terrain, device limits, or partial API/FIT failures.
- Next step: one practical training or data-collection action when appropriate.
